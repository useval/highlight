### `CodeField`

A code editor: a multi-line `TextField` driven by a
`HighlightTextController`, which stays fast on large documents.

```dart
CodeField(controller: HighlightTextController(language: dartLanguage))
```

Typing follows `editing`: Enter keeps the indentation, brackets and
quotes close themselves, and the bracket at the caret is matched. Keys
follow `shortcuts`: Tab and Shift+Tab indent and outdent, and Ctrl+/
(Cmd+/ on Apple platforms) toggles comments. Each key sends an `Intent`
(`IndentCodeIntent`, `OutdentCodeIntent`, `ToggleCommentIntent`); an
`Actions` widget above the field can override what they do.

Set `lineNumbers` for a gutter, `highlightedLines` to mark lines, and
`highlightCurrentLine` to mark the caret's line. These are painted from
the text's own layout, so wrapped lines line up.

Laying out a text field is proportional to its styled runs, so for
documents longer than `styleAllBelow` lines only the visible lines, plus
`styleMargin` lines on each side, are colored. The window follows scrolling
(of the field itself or of an enclosing scroll view) and is computed from
the laid-out text, so wrapped lines are handled exactly.

The field is built on `material_ui`'s `TextField`, so it needs a
`material_ui` `MaterialApp` (or `Material`) above it. Code is always
laid out left to right, even in a right-to-left app.

### `CodeEditing`

Editing behavior for `CodeField`: what typing, Enter and Backspace do
beyond inserting text.

Brackets, quotes and comment markers come from the language's
`EditingSyntax`, unless `syntax` overrides them.

```dart
CodeField(
  controller: controller,
  editing: const CodeEditing(autoClose: false),
)
```

Use `CodeEditing.none` to turn every behavior off.

```dart
const CodeEditing({
  bool autoIndent = true,
  bool autoClose = true,
  bool wrapSelection = true,
  bool matchBrackets = true,
  EditingSyntax? syntax,
})
```

Creates editing behavior. Everything is on by default.

| Field | Type | Default | Description |
|---|---|---|---|
| `autoIndent` | `bool` | `true` | Whether Enter keeps the current line's indentation, adds a level after an opening bracket or `:`, and moves a closing bracket right after the caret onto its own line. |
| `autoClose` | `bool` | `true` | Whether typing an opening bracket or quote also inserts its closing one. |
| `wrapSelection` | `bool` | `true` | Whether typing an opening bracket or quote over a selection wraps the selection instead of replacing it. |
| `matchBrackets` | `bool` | `true` | Whether the bracket next to the caret and its match are marked with a background (`CodeField.bracketColor`). The bracket before the caret is tried first, then the one after it. |
| `syntax` | `EditingSyntax?` |  | Comment markers, brackets and quotes to use instead of the language's. |

<details>
<summary><code>autoClose</code>: more</summary>

Brackets close when the caret is followed by whitespace, the end of
the text or a closing character such as `)` or `;`. Quotes also stay
single after a letter or digit and inside strings and comments.
Typing a closer that was inserted automatically steps over it, and
Backspace between an empty automatic pair deletes both.

</details>

| Member | Type | Description |
|---|---|---|
| `static none` | `CodeEditing` | Plain text editing: no auto-indent, auto-closing, wrapping or bracket matching. |
| `syntaxFor(Grammar language)` | `EditingSyntax` | The syntax used for `language`: `syntax`, or the language's own. |
| `copyWith({…})` | `CodeEditing` | Returns a copy with the given fields replaced. |

### `IndentCodeIntent`

Indents the selected lines, or inserts an indent at the caret. Bound to
Tab in `CodeField`.

```dart
const IndentCodeIntent()
```

Creates an indent intent.

### `OutdentCodeIntent`

Removes one indent from the selected lines. Bound to Shift+Tab in
`CodeField`.

```dart
const OutdentCodeIntent()
```

Creates an outdent intent.

### `ToggleCommentIntent`

Comments or uncomments the selected lines. Bound to Ctrl+/ (Cmd+/ on
Apple platforms) in `CodeField`.

```dart
const ToggleCommentIntent()
```

Creates a toggle-comment intent.

### `toggleComment`

Comments or uncomments the lines touched by the selection, using
`syntax`'s markers. Returns `null` when the language has no comments.

With a line comment marker, the lines are uncommented when every
non-blank one already starts with the marker, and commented otherwise.
Markers are aligned at the smallest indentation, and blank lines are
left alone. `result`, when it highlights `value`'s text, makes sure a
marker inside a string is not taken for a comment.

With only a block comment, as in CSS or HTML, the selection (or the
caret's line) is wrapped in the markers, or unwrapped if it already is.

```dart
TextEditingValue? toggleComment(
  TextEditingValue value,
  EditingSyntax syntax, {
  HighlightResult? result,
})
```
