### `Grammar`

A language grammar: an ordered list of `Rule`s plus a named repository of
reusable rule lists.

Grammars are immutable and usually `const`, so an unused grammar costs
nothing and is tree-shaken away. A grammar is compiled lazily the first
time it is used and the compiled form is cached for its lifetime.

When several rules can match, the one that starts earliest wins. Among
rules starting at the same position, the one listed first wins.

```dart
const Grammar({
  required String name,
  required List<Rule> rules,
  List<String> aliases = const [],
  List<String> fileExtensions = const [],
  List<String> fileNames = const [],
  Map<String, List<Rule>> repository = const {},
  bool caseInsensitive = false,
  bool unicode = false,
  List<String> shebangs = const [],
  List<String> signatures = const [],
  String? restartLine,
  bool detectable = true,
  EditingSyntax? editing,
})
```

Creates a grammar.

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | `String` | *required* | Canonical, lower-case language name, such as `dart`. |
| `aliases` | `List<String>` | `const []` | Other names this language is known by, such as `js` for `javascript`. |
| `fileExtensions` | `List<String>` | `const []` | File extensions without the dot, such as `dart` or `json`. |
| `fileNames` | `List<String>` | `const []` | Whole file names, such as `Dockerfile` or `CMakeLists.txt`. These take priority over `fileExtensions`. |
| `rules` | `List<Rule>` | *required* | Rules active at the top level of a document. |
| `repository` | `Map<String, List<Rule>>` | `const {}` | Named rule lists that `IncludeRule` can reference. |
| `caseInsensitive` | `bool` | `false` | Whether patterns and keywords ignore case. |
| `unicode` | `bool` | `false` | Whether patterns are compiled in unicode mode. |
| `shebangs` | `List<String>` | `const []` | Interpreter names that identify this language in a `#!` first line, such as `python` or `bash`. Used by language detection. |
| `signatures` | `List<String>` | `const []` | Patterns that strongly suggest this language, such as `^import 'package:`. Used by language detection. |
| `restartLine` | `String?` |  | Lines that no rule looks past, such as blank lines in Markdown. |
| `detectable` | `bool` | `true` | Whether `LanguageDetector` may pick this grammar. Off for catch-all grammars such as plain text and the generic fallback. |
| `editing` | `EditingSyntax?` |  | How code in this language is edited: comment markers, brackets and quotes. When `null`, `EditingSyntax.of` derives them from the grammar's comment and string blocks. |

<details>
<summary><code>restartLine</code>: more</summary>

After an edit, `IncrementalHighlighter` normally re-scans from the line
before the edit, which is enough when no rule's pattern reads more
than one line ahead. A grammar whose rules can (a Markdown code span
may wrap across a whole paragraph) sets this, and re-scanning then
starts at the nearest earlier line matching it.

</details>

|---|---|---|
| `extend({…})` | `Grammar` | Returns a new grammar based on this one. |
| `withKeywords({…})` | `Grammar` | Returns this grammar with its keyword tables changed. |
| `validate()` | `void` | Compiles every part of the grammar now, so mistakes surface at once instead of the first time a region is used. |

<details>
<summary><code>extend</code>: more</summary>

`rules` are placed *before* the existing top-level rules, so they take
priority. `repository` entries are added, replacing entries with the
same name. This is how you add or override syntax without rewriting a
grammar.

</details>

<details>
<summary><code>withKeywords</code>: more</summary>

`add` maps a scope to words that get it, such as
`{Scopes.keyword: ['defer']}`; a word already in another scope moves.
Words in `remove` are removed from every scope, so they highlight like
any other identifier. Applies to every `KeywordRule` in the grammar,
including those inside regions and the repository.

```dart
final myDart = dartLanguage.withKeywords(
  add: {Scopes.typeBuiltin: ['Widget', 'BuildContext']},
  remove: ['get', 'set'],
);
```

</details>

<summary><code>validate</code>: more</summary>

### `Rule`

A single grammar rule.

Patterns are Dart `RegExp` sources compiled with `multiLine: true`, so `^`
and `$` match at line boundaries. Named capture groups are not allowed,
because rules are combined into a single expression per state.

```dart
const Rule()
```

Base constructor for rules.

### `TokenRule`

Matches `pattern` and marks the match with `scope`.

`captures` maps capture group numbers inside `pattern` to scopes. Captured
groups must appear in order and must not overlap. Each captured text is
located by searching the match after the previous capture, so it must
not also occur earlier in that stretch: in `\w+\.(\w+)` on `ab.a`, the
capture `a` would mark the first `a`. Where that can happen, match only
the part to scope and put the context in a lookaround, as in
`(?<=\w\.)\w+`.

```dart
const TokenRule(
  String pattern, {
  String? scope,
  Map<int, String> captures = const {},
})
```

Creates a token rule.

| Field | Type | Default | Description |
|---|---|---|---|
| `pattern` | `String` | *required* | Regular expression source to match. |
| `scope` | `String?` |  | Scope for the whole match, or `null` for no scope. |
| `captures` | `Map<int, String>` | `const {}` | Scopes for capture groups inside `pattern`, keyed by group number. |

### `RegionRule`

A region that starts at `begin` and ends at `end`, with its own `rules`
active in between.

Regions nest: strings containing interpolations, comments containing
nested comments, and so on. The `end` pattern is tried before `rules` at
the same position.

A region can hand its content to another language: set `embed` to a
grammar (for example CSS inside an HTML `<style>` element), or set
`embedCapture` to a capture group of `begin` whose text names the
language (for example the info string of a Markdown code fence). Named
languages are looked up in the `Highlighter`'s registry; when none is
found, `rules` apply instead. The `end` of an embedding region closes it
from any depth: a code fence ends even inside an unterminated string of
the embedded language, just as `</script>` ends a script in a browser.

Set `endReferencesBegin` when the end depends on what the begin matched,
such as a heredoc delimiter: `\1`–`\9` in `end` then stand for the text
of those capture groups of `begin`.

```dart
const RegionRule({
  required String begin,
  required String end,
  String? scope,
  String? beginScope,
  String? endScope,
  Map<int, String> beginCaptures = const {},
  Map<int, String> endCaptures = const {},
  List<Rule> rules = const [],
  Grammar? embed,
  int? embedCapture,
  bool endReferencesBegin = false,
})
```

Creates a region rule.

| Field | Type | Default | Description |
|---|---|---|---|
| `begin` | `String` | *required* | Pattern that opens the region. |
| `end` | `String` | *required* | Pattern that closes the region. |
| `scope` | `String?` |  | Scope for the whole region, including both delimiters. |
| `beginScope` | `String?` |  | Extra scope for the opening delimiter, nested inside `scope`. |
| `endScope` | `String?` |  | Extra scope for the closing delimiter, nested inside `scope`. |
| `beginCaptures` | `Map<int, String>` | `const {}` | Scopes for capture groups inside `begin`. |
| `endCaptures` | `Map<int, String>` | `const {}` | Scopes for capture groups inside `end`. |
| `rules` | `List<Rule>` | `const []` | Rules active inside the region. |
| `embed` | `Grammar?` |  | Language used for the region's content instead of `rules`. |
| `embedCapture` | `int?` |  | Capture group of `begin` naming the language for the content. |
| `endReferencesBegin` | `bool` | `false` | Whether `\1`–`\9` in `end` refer to capture groups of `begin`. |

### `KeywordRule`

Matches words with `word` and scopes them by table lookup.

A lookup is much faster than one large alternation of every keyword.
`keywords` maps a scope to the words that get it. When a matched word is
not in the table, each rule in `otherwise` is tried at the same position,
which is how heuristics such as "capitalised words are types" work.

```dart
const KeywordRule(
  Map<String, List<String>> keywords, {
  String word = r'(?<!\w)[A-Za-z_]\w*',
  List<TokenRule> otherwise = const [],
})
```

Creates a keyword rule.

| Field | Type | Default | Description |
|---|---|---|---|
| `keywords` | `Map<String, List<String>>` | *required* | Scope to words, such as `{'keyword': ['if', 'else']}`. |
| `word` | `String` | `r'(?<!\w)[A-Za-z_]\w*'` | Pattern for a single word. |
| `otherwise` | `List<TokenRule>` | `const []` | Rules tried, in order, on words that are not keywords. |

### `BlockRule`

The built-in blocks cover what most languages repeat: comments, strings,

### `QuotedString`

A string between `quote` and `end` (default: `quote`).

- `prefix` is a pattern allowed before the quote, such as `[rRbB]?`.
- `escape` starts an escape sequence (default `\`); `null` for none.
- `doubled` treats a doubled quote as an escaped quote (SQL, Pascal,
  VB, CSV).
- `multiline` lets the string span lines; otherwise it also ends at the
  end of the line, so an unclosed quote cannot swallow the file.
- `lastInRun` closes on the last delimiter of a run of quote
  characters, as Scala and Kotlin `"""` strings do: `""""x""""`
  holds `"x"`.
- `rules` adds rules inside, such as interpolation.

```dart
const QuotedString(
  String quote, {
  String? end,
  String? prefix,
  String? escape = r'\',
  bool doubled = false,
  bool multiline = false,
  bool lastInRun = false,
  List<Rule> rules = const [],
  String scope = Scopes.string,
})
```

Creates a string block.

| Field | Type | Default | Description |
|---|---|---|---|
| `quote` | `String` | *required* | Opening quote. |
| `end` | `String?` |  | Closing quote, when different from `quote`. |
| `prefix` | `String?` |  | Pattern allowed immediately before the quote. |
| `escape` | `String?` | `r'\'` | Escape character, or `null` for none. |
| `doubled` | `bool` | `false` | Whether a doubled closing quote is an escape. |
| `multiline` | `bool` | `false` | Whether the string may span lines. |
| `lastInRun` | `bool` | `false` | Whether the string closes on the last delimiter of a run of quotes. |
| `rules` | `List<Rule>` | `const []` | Extra rules inside the string. |
| `scope` | `String` | `Scopes.string` | Scope of the string. |

### `CommonRules`

Common heuristics for identifiers that are not keywords, for use in
`KeywordRule.otherwise`.

| Member | Type | Description |
|---|---|---|
| `static capitalizedType` | `TokenRule` | A capitalised identifier is a type (`Foo`, `_Bar`). |
| `static functionCall` | `TokenRule` | An identifier followed by `(` or `<T>(` is a function. |
| `static memberCall` | `TokenRule` | After a `.`, a called name is a function (`list.add(`). |

### `EditingSyntax`

How code in a language is edited: its comment markers, brackets and
quotes.

Editors use this to toggle comments, auto-close brackets and quotes and
match brackets. Set it on a grammar with `Grammar.editing`; read it with
`EditingSyntax.of`, which derives one from the grammar's `LineComment`,
`BlockComment` and `QuotedString` blocks when none is set.

```dart
const myLanguage = Grammar(
  name: 'mine',
  rules: [...],
  editing: EditingSyntax(lineComment: '--', quotes: '"'),
);
```

```dart
const EditingSyntax({
  String? lineComment,
  (String, String)? blockComment,
  String brackets = '()[]{}',
  String quotes = '"\'',
})
```

Creates editing conventions for a language.

| Field | Type | Default | Description |
|---|---|---|---|
| `lineComment` | `String?` |  | Text that starts a line comment, such as `//` or `#`, or `null` if the language has none. |
| `blockComment` | `(String, String)?` |  | The opening and closing text of a block comment, such as `('/*', '*/')`, or `null` if the language has none. |
| `brackets` | `String` | `'()[]{}'` | Bracket pairs, as consecutive opening and closing characters: `'()[]{}'` stands for `()`, `[]` and `{}`. Used for matching and auto-closing. |
| `quotes` | `String` | `'"\''` | Characters that open and close a string, such as `"` and `'`. Auto-closed like brackets, except after a letter or digit, so `don't` is left alone. Leave out characters with another meaning, such as `'` in Rust lifetimes or Lisp quoting. |

| Member | Type | Description |
|---|---|---|
| `static cStyle` | `EditingSyntax` | `//` line comments, `/* */` block comments, and `"` `'` quotes: C, Java, Kotlin, Swift and most of their relatives. |
| `static hashStyle` | `EditingSyntax` | `#` line comments: shells, Python, Ruby, YAML and many config formats. |
| `static markupStyle` | `EditingSyntax` | `<!-- -->` block comments: HTML, XML and Markdown. |
| `static none` | `EditingSyntax` | No comments, brackets or quotes: plain text. |
| `copyWith({…})` | `EditingSyntax` | Returns a copy with the given fields replaced. |
| `closerOf(String open)` | `String?` | The closing character for `open`, or `null` if `open` opens nothing. |
| `static of(Grammar grammar)` | `EditingSyntax` | The editing conventions of `grammar`: its `Grammar.editing`, or, when that is unset, conventions derived from its comment and string blocks. |

<details>
<summary><code>static of</code>: more</summary>

Derivation looks at the top-level rules and the repository. The
