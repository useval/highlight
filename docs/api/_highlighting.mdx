### `Highlighter`

Highlights source code.

```dart
final result = const Highlighter().highlight(code, language: dartLanguage);
print(result.toHtml());
```

A highlighter holds no mutable state, so one instance can be shared, and
it is safe to use from any isolate.

```dart
const Highlighter({
  LanguageRegistry? registry,
})
```

Creates a highlighter.

`registry` enables lookup by name and resolves languages named inside
the code, such as Markdown code fences.

| Field | Type | Description |
|---|---|---|
| `registry` | `LanguageRegistry?` | Languages available by name, if any. |

| Member | Type | Description |
|---|---|---|
| `highlight(String code, {required Grammar language})` | `HighlightResult` | Highlights `code` with `language`. |
| `highlightByName(String code, {required String name})` | `HighlightResult` | Highlights `code` with the language registered as `name` or an alias, or the registry's fallback. |
| `toHtml(…)` | `String` | Highlights `code` with `language` and renders it as HTML. |

### `HighlightResult`

The output of highlighting: `code` split into contiguous tokens.

Tokens are stored flat, as two parallel integer lists, rather than as a
tree of objects. Token `i` covers `code[tokenStart(i), tokenEnd(i))` and
carries a scope stack id from `scopes`. Tokens always cover all of `code`
with no gaps, and neighbouring tokens never share a stack.

A result never changes once made, though its `scopes` table may gain
stacks (see there). It can be sent to another isolate as it is.

| Field | Type | Description |
|---|---|---|
| `code` | `String` | The highlighted source. |
| `language` | `Grammar` | Grammar used to highlight `code`. |
| `scopes` | `ScopeTable` | Scope names and stacks referenced by the tokens. |
| `tokenCount` | `int` | Number of tokens. |

<details>
<summary><code>scopes</code>: more</summary>

Results from one `IncrementalHighlighter` share a table that grows as
the document is edited. A stack id never changes meaning, so styles
cached per stack id stay valid; later results may only add stacks.

</details>

| `tokenEnd(int index)` | `int` | End offset (exclusive) of token `index`. |

<details>
<summary><code>isInsideStringOrComment</code>: more</summary>

Unlike `isStringOrCommentAt`, this answers for a position between
characters: right after a closing quote is outside the string, while
the end of a line comment or of an unterminated string is inside.
`syntax` supplies the block comment marker; it defaults to
`EditingSyntax.of` the `language`.

</details>

<details>
<summary><code>matchingBracket</code>: more</summary>

`brackets` lists pairs as consecutive opening and closing characters,
and defaults to the `language`'s `EditingSyntax.brackets`. Brackets
inside strings and comments are skipped, so `f(")")` matches
correctly. The search walks tokens, jumping over a whole string or
comment at once.

</details>

### `HighlightToken`

A lightweight view of one token in a `HighlightResult`.

| Field | Type | Description |
|---|---|---|
| `index` | `int` | Position of this token in the result. |

| Member | Type | Description |
|---|---|---|
| `start` | `int` | Start offset in the source. |
| `end` | `int` | End offset (exclusive) in the source. |
| `stack` | `int` | Scope stack id. |
| `text` | `String` | Source text covered by this token. |
| `scope` | `String?` | Innermost scope, or `null` for plain text. |
| `scopes` | `List<String>` | Scopes from the outermost to the innermost. |

### `ScopeTable`

Interned scope names and scope stacks for one highlight result.

Every token records a single stack id. A stack is a chain of scopes from
the outside in, such as `string > interpolation > keyword`. Stack `0` is
the root and has no scope. A parent always has a smaller id than its
children, so renderers can resolve styles in a single forward pass.

| Member | Type | Description |
|---|---|---|
| `static root` | `int` | Id of the root stack, which has no scope. |
| `stackCount` | `int` | Number of stacks, including the root. |
| `parentOf(int stack)` | `int` | Parent of `stack`, or `-1` for the root. |
| `scopeOf(int stack)` | `String?` | Innermost scope of `stack`, or `null` for the root. |
| `scopesOf(int stack)` | `List<String>` | Scopes of `stack` from the outermost to the innermost. |
| `pathOf(int stack)` | `List<int>` | Stack ids from the outermost to `stack`, excluding the root. |
| `isStringOrComment(int stack)` | `bool` | Whether `stack` is inside a string, comment or regular expression. |
| `isComment(int stack)` | `bool` | Whether `stack` is inside a comment. |

<details>
<summary><code>isStringOrComment</code>: more</summary>

An interpolation inside a string, such as `${x}`, is code again: its
stacks are not.

</details>
