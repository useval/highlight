### `ValTheme`

A color theme: a `root` style plus a style per scope.

A scope's style builds on those of its dotted prefixes: `title.function`
takes the fields set for `title`, then those set for `title.function`.
This is how CSS classes from `toCss` combine too.

```dart
const ValTheme({
  required String name,
  Style root = const Style(),
  Map<String, Style> styles = const {},
  bool dark = false,
})
```

Creates a theme.

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | `String` | *required* | Theme name. |
| `root` | `Style` | `const Style()` | Base style for all code, including the background color. |
| `styles` | `Map<String, Style>` | `const {}` | Style per scope. |
| `dark` | `bool` | `false` | Whether this is a dark theme. |

| Member | Type | Description |
|---|---|---|
| `ValTheme.fromVsCode(Map<String, Object?> json, {String? name})` | `ValTheme` | Builds a theme from a decoded VS Code color theme (the JSON object of a `*-color-theme.json` file). |
| `ValTheme.fromVsCodeJson(String source, {String? name})` | `ValTheme` | Like `ValTheme.fromVsCode`, from the text of a theme file. Comments and trailing commas (JSONC) are allowed. |
| `lookup(String scope)` | `Style?` | Style for `scope` alone, without inheriting from enclosing scopes: the styles of `a`, `a.b` and `a.b.c` merged in that order for `a.b.c`, or `null` if none is set. |
| `resolve(ScopeTable table)` | `List<Style>` | Effective style of every stack in `table`, indexed by stack id. |
| `copyWith({…})` | `ValTheme` | Returns a copy with the given fields replaced. |
| `extend({String? name, Style? root, Map<String, Style>? styles})` | `ValTheme` | Returns a theme built on this one. |
| `toCss({String classPrefix = 'vh-', String rootClass = 'vh'})` | `String` | CSS for this theme, matching the classes written by `HtmlRenderer`. |

### `Style`

Visual style for one scope. Unset fields inherit from the enclosing scope.

Colors are ARGB integers such as `0xFF1E7A3A`, so styles are `const` and
cost nothing to convert on any platform.

```dart
const Style({
  int? color,
  int? background,
  bool? bold,
  bool? italic,
  bool? underline,
  bool? strikethrough,
})
```

Creates a style.

| Field | Type | Description |
|---|---|---|
| `color` | `int?` | Foreground color as ARGB. |
| `background` | `int?` | Background color as ARGB. |
| `bold` | `bool?` | Bold text. |
| `italic` | `bool?` | Italic text. |
| `underline` | `bool?` | Underlined text. |
| `strikethrough` | `bool?` | Struck-through text. |

| Member | Type | Description |
|---|---|---|
| `isEmpty` | `bool` | Whether every field is unset. |
| `merge(Style? other)` | `Style` | Returns this style with the set fields of `other` applied on top. |
| `copyWith({…})` | `Style` | Returns a copy with the given fields replaced. |
| `toCss()` | `String` | CSS declarations for this style, such as `color:#1e7a3a;`. |

### `CodeTheme`

Sets `CodeThemeData` for the code widgets below it.

It works in any app, whatever its design system. Put one above your
app's content, for example in `MaterialApp.builder`, so it can follow
the app's own brightness:

```dart
MaterialApp(
  builder: (context, child) => CodeTheme(
    data: CodeThemeData(
      light: sepiaTheme,
      dark: dimTheme,
      brightness: Theme.of(context).brightness,
    ),
    child: child!,
  ),
)
```

Without a `CodeTheme`, the widgets use `lightTheme` or `darkTheme` by
the platform's brightness.

```dart
const CodeTheme({
  Key? key,
  required CodeThemeData data,
  required Widget child,
})
```

Provides `data` to the code widgets in `child`.

| Field | Type | Default | Description |
|---|---|---|---|
| `data` | `CodeThemeData` | *required* | The defaults. |

| Member | Type | Description |
|---|---|---|
| `static maybeOf(BuildContext context)` | `CodeThemeData?` | The nearest `CodeThemeData`, if any. |
| `static of(BuildContext context)` | `CodeThemeData` | The nearest `CodeThemeData`, or the default one. |
| `static brightnessOf(BuildContext context)` | `Brightness` | The brightness the code widgets use: `CodeThemeData.brightness`, or the platform's. |
| `static resolve(BuildContext context, [ValTheme? override])` | `ValTheme` | The `ValTheme` to use: `override` if given, otherwise the default for `brightnessOf`. |
| `static textStyleOf(BuildContext context, [TextStyle? override])` | `TextStyle` | The default code text style: monospace, merged with `CodeThemeData.textStyle` and then `override`. |

<summary><code>static textStyleOf</code>: more</summary>

Letter and word spacing are fixed at zero so an app-wide text theme
cannot stretch code or its line numbers.

</details>

### `CodeThemeData`

App-wide defaults for the code widgets, provided by a `CodeTheme`.

Anything set directly on a widget wins over these defaults.

```dart
const CodeThemeData({
  ValTheme? light,
  ValTheme? dark,
  Brightness? brightness,
  TextStyle? textStyle,
  EdgeInsetsGeometry? padding,
  bool? lineNumbers,
})
```

Creates code defaults.

| Field | Type | Description |
|---|---|---|
| `light` | `ValTheme?` | Theme used when `brightness` is light. Defaults to `lightTheme`. |
| `dark` | `ValTheme?` | Theme used when `brightness` is dark. Defaults to `darkTheme`. |
| `brightness` | `Brightness?` | Whether to use `light` or `dark`. Defaults to the platform's brightness, from `MediaQuery`. Set it from your app's theme when the app does not follow the platform: |
| `textStyle` | `TextStyle?` | Base text style for code, merged over the default monospace style. |
| `padding` | `EdgeInsetsGeometry?` | Padding around code in `CodeView`. |
| `lineNumbers` | `bool?` | Whether `CodeView` and `CodeField` show line numbers. |
